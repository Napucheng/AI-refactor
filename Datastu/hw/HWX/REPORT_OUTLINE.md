# Homework X Report Outline

## 1. 算法设计思路

- 采用事件驱动调度框架，事件包括即时订单到达、快递员空闲、预订单进入激活窗口。
- 将订单拆分为预订单与即时订单两类处理：
  - 即时订单到达后进入待分配池，优先从最紧急的一批订单中选择。
  - 预订单虽然营业前已知，但只在接近“最晚安全派发时刻”时激活，避免过早占用快递员。
- 调度时优先考虑即时订单；若当前没有可成功送达的即时订单，再尝试分配预订单。
- 候选分配使用统一贪心准则：优先选择剩余时间裕量最小、送达更早的方案，并用快递员编号和订单编号稳定打破平局。

## 2. 性能测试结果与分析

- 测试不同订单规模下的运行时间，例如 100、1000、5000 单。
- 记录总成功单数、总收入、平均每单决策耗时。
- 比较以下策略的效果差异：
  - 不区分订单类型的简单贪心
  - 当前实现的“即时优先 + 预订单延迟激活”策略
- 分析两个关键参数的影响：
  - `PREORDER_LOOKAHEAD`
  - `MAX_PENDING_SCAN`

## 3. 遇到的困难与解决方案

- 难点 1：预订单允许提前出发，但过早出发会影响后续即时订单接单能力。
  - 解决：对预订单设置激活窗口，而不是在营业开始时全部立即分配。
- 难点 2：输出必须满足评测器的物理可行性检查。
  - 解决：所有送达时间统一通过题目公式精确计算，不做手工估算。
- 难点 3：Python 下需要在正确性和效率之间平衡。
  - 解决：即时订单只从最紧急的前若干笔中筛选，降低每次决策的扫描范围。
